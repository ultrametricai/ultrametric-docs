---
title: "Troubleshooting"
description: "Fix sign-in, process access, skill setup, and saved-work problems."
---

## The CLI command is missing

Run `ultrametric --version` and `ultrametric --help` in the environment your agent uses. These docs cover 0.4.1. If `process open` or `context` is missing, [update the CLI](/cli/install) and check that the agent uses the expected Node environment.

## Sign-in fails or returns AUTH_REQUIRED

Check the selected environment and run `ultrametric auth status --json`. Start a new [CLI login](/cli/install) if needed. With MCP, reconnect through the host's OAuth flow.

A saved CLI session can expire. If a request returns HTTP 401, sign in again. Keep production and staging sessions separate.

## The process list is empty or an ID is unavailable

Confirm the account in MCP `status` or CLI login status. The catalog is filtered by account access. Use an ID from the current catalog rather than one copied from another account.

For a known ID, MCP `status` with `processId` reports `releaseAccess` and `available`. A selected version can also be unavailable; omit the version to request the latest available guide.

## Company context is denied or missing

Check the selected organization and your [context permissions](/mcp/authentication). Ask a workspace administrator to review access if needed.

If the information was saved with CLI `companies` or `assessments`, look in local storage. Those files are not automatically synchronized to hosted context.

## A save timed out or conflicted

Retry an uncertain save with the exact same input and update key. Do not create another update key for that retry. After a conflict, read current state and use the current record revision when preparing a new change. See [save progress](/guides/save-progress).

## A project skill conflicts or does not appear

Run `ultrametric init --dry-run --json` to see which files would change. Review any differing file before using `--force` to replace it. Keep custom project guidance outside the generated skill.

If the skill file exists but is unavailable to the agent, start a fresh session in the project. Check that the CLI is on the agent's executable path.

## A local template does not match the process schema

Update the CLI or choose a compatible published process version with `--process-version`. Use the returned guide's schema when preparing the result.

## An MCP view does not display

Ask the agent to use the tool's text or structured response. Optional views depend on the host's capabilities.

## Report a problem

Include the CLI or host version, environment, operation, error code, and request ID if one was returned. Remove access tokens, login codes, private payloads, and unnecessary local paths before sharing the report.
