title: "Troubleshoot access and saved work"
description: "Resolve version, authentication, catalog, and context problems without changing scope."
---

> Internal documentation draft. Recovery guidance follows the inspected CLI and API behavior.

| Symptom | Check | Next step |
| --- | --- | --- |
| `process open` or `context` is missing | `ultrametric --version` and `--help` | This reference targets 0.4.1; check the active Node environment and installed executable |
| `AUTH_REQUIRED` or HTTP 401 | Selected environment and login | Complete login for that environment; local session presence is not proof of API acceptance |
| Empty process list | MCP `status`, account, release access | Verify availability for the account; do not use a catalog copied from another user |
| Process/version not found | ID and version from current catalog | Use the returned ID; `status` can inspect access to a supplied process ID |
| Private context denied | Selected organization and required permissions | Resolve membership/scope; changing a request's organization ID cannot grant access |
| Company missing from hosted results | Where it was saved | CLI local `companies` records are not automatically synchronized |
| Update conflicts or uncertain save | Current record revision and prior update key | Read current state; retry uncertain writes only with the same key and exact input |
| Skill setup reports a conflict | Preview with `init --dry-run` | Review the existing file before replacing it |
| Process schema rejects a local adapter template | CLI and guide version | Update the client or choose a compatible published process version |
| Optional MCP view does not render | Host capabilities and tool text | Use structured/text output; report the exact host/version for later verification |

For a report, record the client version, selected environment, operation, error code, and request ID if supplied. Remove bearer tokens, login codes, private payloads, and local paths that are not needed. A health check only establishes service liveness; it does not verify OAuth, catalog access, persistence, or successful process work.
